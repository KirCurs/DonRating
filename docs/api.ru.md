# HTTP API

[English](api.en.md)

Для локального запуска базовый адрес — `http://127.0.0.1:8080`. В примерах он задан в `BASE_URL`. Тело POST-запроса должно содержать один JSON-объект размером не более 4096 байт. Неизвестные поля и дополнительные JSON-значения отклоняются. Отправляйте заголовок `Content-Type: application/json`.

## Авторизация

Защищённые маршруты принимают `Authorization: Bearer <token>`. Для сотрудника используется `ADMIN_TOKEN`, для планшета — его токен из `DEVICE_TOKENS_JSON` или ключ, выданный при регистрации. Ключ одного планшета не даёт доступа к другому. Если токены не настроены, доступ ограничен запросами с loopback и локальным `Host`. Если есть заголовок `Origin`, его хост должен совпадать с `Host` запроса. Страницы интерфейса открываются без токена. API проверяет ключ отдельно.

## Маршруты

| Метод и путь | Доступ | Успешный ответ |
| --- | --- | --- |
| `GET /health` | Открытый | 200, текст `ok` |
| `GET /ready` | Открытый | 200, `{"ready":true}`. Если БД недоступна, 503 |
| `GET /version` | Открытый | 200, версия текстом |
| `POST /api/admin/devices` | Сотрудник | 201, ID, имя и ссылка подключения планшета |
| `POST /requests` | Сотрудник | 201, созданное приглашение |
| `POST /request` | Сотрудник | То же, что `POST /requests` |
| `GET /requests/{id}` | Сотрудник | 200, приглашение |
| `GET /api/admin/state` | Сотрудник | 200, устройства и их последние приглашения |
| `GET /api/tablets/{device_id}/state` | Планшет | 200, состояние с активным приглашением или `null` в поле `request` |
| `POST /api/tablets/{device_id}/ack` | Планшет | 200, `{"ok":true}` |
| `POST /api/tablets/{device_id}/answer` | Планшет | 200, приглашение с ответом |
| `POST /rating` | Сотрудник | 200, приглашение с ответом. Маршрут для совместимости |
| `GET /rating/{request_id}` | Сотрудник | 200, `{"request_id":"…","score":5}` |

## Объект приглашения

```json
{
  "id": "b7726c54-3561-490e-86b2-4d7e8c97a100",
  "device_id": "reception-1",
  "status": "answered",
  "created_at": "2026-11-16T10:00:00Z",
  "expires_at": "2026-11-16T10:00:30Z",
  "answered_at": "2026-11-16T10:00:05Z",
  "score": 5
}
```

Поля `answered_at` и `score` отсутствуют до принятия ответа. Время передаётся по RFC 3339. Возможные статусы — `pending`, `displayed`, `answered`, `expired`. UUID генерирует сервер.

## Последовательность запросов

Планшет обращается к своему `/state`, чтобы сервер отметил его как подключённый. Открытая страница планшета делает это автоматически. В примере `ADMIN_TOKEN` и `TABLET_TOKEN` уже заданы в окружении. `TABLET_TOKEN` содержит ключ выбранного планшета.

```sh
export BASE_URL='http://127.0.0.1:8080'
curl -sS "$BASE_URL/api/tablets/reception-1/state" \
  -H "Authorization: Bearer $TABLET_TOKEN"

curl -sS -X POST "$BASE_URL/requests" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"reception-1"}'
```

Скопируйте `id` из ответа в `REQUEST_ID`. По умолчанию на ответ даётся 30 секунд, а отметка «В сети» сохраняется восемь секунд после последнего опроса. Для ручной проверки удобно держать вкладку планшета открытой.

```sh
export REQUEST_ID='UUID_FROM_RESPONSE'
curl -sS -X POST "$BASE_URL/api/tablets/reception-1/ack" \
  -H "Authorization: Bearer $TABLET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"id\":\"$REQUEST_ID\"}"

curl -sS -X POST "$BASE_URL/api/tablets/reception-1/answer" \
  -H "Authorization: Bearer $TABLET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"$REQUEST_ID\",\"score\":5}"
```

Повтор той же оценки возвращает 200 с сохранённым ответом даже после исходного срока. Другая оценка для отвеченного приглашения возвращает 409. Если приглашение осталось без ответа к истечению срока, попытка ответить вернёт 410.

## Состояние экранов

Ответ планшету содержит `device_id`, `server_now`, `request`, `slideshow_url` и `slideshow_configured`. Если активного приглашения нет, `request` равно `null`. Если плеер настроен, `slideshow_url` содержит `/slideshow/`, иначе — пустую строку.

Ответ сотруднику содержит `server_now`, `request_ttl_seconds`, `slideshow_configured` и `devices`. В каждом элементе `devices` есть `id`, `name`, `online`, `last_seen` (RFC 3339 или `null`) и `request` (последнее приглашение или `null`). Последнее приглашение может быть закрытым.

## Ошибки

Обработчики и проверка доступа возвращают ошибки в JSON. Для обработки в клиенте используйте поле `error`.

```json
{"error":"expired","message":"Время для ответа истекло"}
```

| HTTP | `error` | Значение |
| --- | --- | --- |
| 400 | `invalid_json` | Тело запроса не соответствует ожидаемому JSON |
| 400 | `unknown_device` | Указан неизвестный планшет при создании приглашения |
| 400 | `invalid_request`, `invalid_rating` | Некорректные данные или оценка вне диапазона 1–5 |
| 401 | `unauthorized` | Ключ отсутствует или неверен |
| 403 | `origin_denied` | Origin запроса не разрешён |
| 404 | `not_found` | Приглашение или оценка не найдены либо приглашение принадлежит другому планшету |
| 404 | `unknown_device` | В маршруте устройства указан неизвестный планшет |
| 409 | `device_offline` | Планшет не в сети |
| 409 | `active_request` | У планшета уже есть активное приглашение |
| 409 | `already_answered` | Попытка изменить ответ или выполнить действие с закрытым приглашением |
| 410 | `expired` | Время для ответа истекло |
| 500 | `storage_error` | Ошибка хранилища |
| 503 | `not_ready` | Проверка готовности не смогла обратиться к БД |

Ошибки маршрутизации и выдачи файлов, включая 404 и 405, могут возвращаться обычным текстом. Маршрут совместимости `POST /rating` принимает `{"request_id":"…","score":5}`. Указанный ID должен принадлежать существующему приглашению. На него действуют обычные ограничения по состоянию и сроку.

## Регистрация планшета

`POST /api/admin/devices` принимает `{"name":"Ресепшен слева"}`. Имя очищается от пробелов по краям и должно содержать от 1 до 100 символов Unicode. Сервер генерирует ID и случайный 256-битный ключ, сохраняет его хеш SHA-256 и возвращает:

```json
{
  "id": "tablet-b7726c54-3561-490e-86b2-4d7e8c97a100",
  "name": "Reception left",
  "tablet_url": "/tablet?device_id=tablet-b7726c54-3561-490e-86b2-4d7e8c97a100#token=GENERATED_SECRET"
}
```

Откройте относительную ссылку на том же адресе, что и приложение. Ключ выдаётся в ответе на регистрацию. В ответах о состоянии устройства его нет. Зарегистрированные планшеты предъявляют ключ даже при локальном подключении. `GET /api/admin/state` возвращает устройства из конфигурации и реестра.

При регистрации возможны ошибки 400 `invalid_device`, 409 `device_conflict`, 500 `registration_failed` и 503 `registration_unavailable`, если хранилище не поддерживает регистрацию. Ошибки БД возвращаются с кодом `storage_error`.

# HTTP API

Default local base URL: `http://127.0.0.1:8080`.
The examples use `$BASE_URL` for this address. POST bodies must contain a single
JSON object, at most 4096 bytes. Unknown fields and additional JSON values
are rejected. Clients should send `Content-Type: application/json`.

## Authorization

Protected routes accept `Authorization: Bearer <token>`.
Receptionist requests use `ADMIN_TOKEN`; tablets use their own token from
`DEVICE_TOKENS_JSON`. A tablet token cannot access another device.
When tokens are unset, access is restricted to loopback requests with a local
Host. If an Origin header is present, its host must match the request Host.
UI pages are accessible without a token; API authorization is checked separately.

## Endpoints

| Method and path | Access | Successful response |
| --- | --- | --- |
| `GET /health` | Public | 200, plain text `ok` |
| `GET /ready` | Public | 200, `{"ready":true}`; 503 if the database check fails |
| `GET /version` | Public | 200, plain text version |
| `POST /requests` | Receptionist | 201, created request |
| `POST /request` | Receptionist | Alias of `/requests` |
| `GET /requests/{id}` | Receptionist | 200, request |
| `GET /api/admin/state` | Receptionist | 200, devices and latest requests |
| `GET /api/tablets/{device_id}/state` | Tablet | 200, active request or `null` within the state object |
| `POST /api/tablets/{device_id}/ack` | Tablet | 200, `{"ok":true}` |
| `POST /api/tablets/{device_id}/answer` | Tablet | 200, answered request |
| `POST /rating` | Receptionist | 200, answered request; compatibility endpoint |
| `GET /rating/{request_id}` | Receptionist | 200, `{"request_id":"…","score":5}` |

## Request object

```json
{
  "id": "b7726c54-3561-490e-86b2-4d7e8c97a100",
  "device_id": "reception-1",
  "status": "answered",
  "created_at": "2026-11-16T10:00:00Z",
  "expires_at": "2026-11-16T10:00:30Z",
  "answered_at": "2026-11-16T10:00:05Z",
  "score": 5
}
```

`answered_at` and `score` are omitted until an answer is accepted.
Timestamps use RFC 3339. Status values are `pending`, `displayed`, `answered`,
and `expired`. UUIDs are generated by the server; the values above are illustrative.

## Request sequence

First, the tablet calls its `/state` endpoint to establish presence.
Keeping the tablet page open performs this automatically.
The examples assume exported `ADMIN_TOKEN` and `TABLET_TOKEN` variables;
`TABLET_TOKEN` must contain this device's value from `DEVICE_TOKENS_JSON`.

```sh
export BASE_URL='http://127.0.0.1:8080'
curl -sS "$BASE_URL/api/tablets/reception-1/state" \
  -H "Authorization: Bearer $TABLET_TOKEN"

curl -sS -X POST "$BASE_URL/requests" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"reception-1"}'
```

Copy the returned `id` into `REQUEST_ID`. Requests expire after 30 seconds
by default; device presence lasts eight seconds after the latest state poll.
For manual checks, keeping the tablet tab open is convenient.

```sh
export REQUEST_ID='UUID_FROM_RESPONSE'
curl -sS -X POST "$BASE_URL/api/tablets/reception-1/ack" \
  -H "Authorization: Bearer $TABLET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"id\":\"$REQUEST_ID\"}"

curl -sS -X POST "$BASE_URL/api/tablets/reception-1/answer" \
  -H "Authorization: Bearer $TABLET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"$REQUEST_ID\",\"score\":5}"
```

Retrying the same score returns 200 with the stored answer, even after its
original deadline. A different score for an answered request returns 409.
An attempt to answer an unanswered request after expiry returns 410.

## Screen state

The tablet response contains `device_id`, `server_now`, `request`,
`slideshow_url`, and `slideshow_configured`. `request` is `null` when there is
no active request. `slideshow_url` is `/slideshow/` when a source is configured,
otherwise an empty string.

The receptionist response contains `server_now`, `request_ttl_seconds`,
`slideshow_configured`, and `devices`. Each device contains `id`, `name`,
`online`, `last_seen` (RFC 3339 or `null`), and `request` (latest request or `null`).
The latest request can include a closed state.

## Errors

Handler and authorization errors use JSON:

```json
{"error":"expired","message":"Время для ответа истекло"}
```

Messages are currently in Russian. Use the machine-readable `error` code
for programmatic handling.

| HTTP | `error` | Meaning |
| --- | --- | --- |
| 400 | `invalid_json` | Body does not match the expected JSON format |
| 400 | `unknown_device` | Unknown tablet when creating a request |
| 400 | `invalid_request`, `invalid_rating` | Invalid data or score outside 1–5 |
| 401 | `unauthorized` | Missing or invalid token |
| 403 | `origin_denied` | Request origin is not allowed |
| 404 | `not_found` | Request or rating not found, or request belongs to another tablet |
| 404 | `unknown_device` | Unknown tablet in a device route |
| 409 | `device_offline` | Tablet is offline |
| 409 | `active_request` | Device already has an active request |
| 409 | `already_answered` | Attempt to change an answer or act on a closed request |
| 410 | `expired` | Request deadline has passed |
| 500 | `storage_error` | Storage operation failed |
| 503 | `not_ready` | Readiness check could not reach the database |

Router and static file errors, including 404/405, may be plain text;
they do not follow the JSON error format above.

The compatibility endpoint `POST /rating` accepts
`{"request_id":"…","score":5}`. It also requires an issued request and enforces
its lifecycle. An arbitrary identifier cannot create a new rating.

# HTTP API

Базовый адрес локального запуска: `http://127.0.0.1:8080`.
В примерах `$BASE_URL` — этот адрес. Тело POST-запросов — один JSON-объект,
не более 4096 байт; неизвестные поля и дополнительные JSON-значения отклоняются.
Клиент должен отправлять `Content-Type: application/json`.

## Авторизация

Защищённые маршруты принимают `Authorization: Bearer <ключ>`.
Для сотрудника используется `ADMIN_TOKEN`, для планшета — его значение из
`DEVICE_TOKENS_JSON`. Ключ планшета не даёт доступа к другому устройству.
Без ключей доступ разрешён только локальным запросам с loopback-адреса
и локальным Host. При наличии заголовка Origin он должен совпадать с Host.
Страницы интерфейса открываются без ключа; API проверяет ключ отдельно.

## Маршруты

| Метод и путь | Доступ | Успешный ответ |
| --- | --- | --- |
| `GET /health` | Открытый | 200, текст `ok` |
| `GET /ready` | Открытый | 200, `{"ready":true}`; при отказе БД 503 |
| `GET /version` | Открытый | 200, текст версии |
| `POST /requests` | Сотрудник | 201, созданное приглашение |
| `POST /request` | Сотрудник | Совместимый вариант `/requests` |
| `GET /requests/{id}` | Сотрудник | 200, приглашение |
| `GET /api/admin/state` | Сотрудник | 200, список устройств и последние приглашения |
| `GET /api/tablets/{device_id}/state` | Планшет | 200, активное приглашение или `null` |
| `POST /api/tablets/{device_id}/ack` | Планшет | 200, `{"ok":true}` |
| `POST /api/tablets/{device_id}/answer` | Планшет | 200, приглашение с ответом |
| `POST /rating` | Сотрудник | 200, приглашение с ответом; совместимый маршрут |
| `GET /rating/{request_id}` | Сотрудник | 200, `{"request_id":"…","score":5}` |

## Объект приглашения

```json
{
  "id": "b7726c54-3561-490e-86b2-4d7e8c97a100",
  "device_id": "reception-1",
  "status": "answered",
  "created_at": "2026-11-16T10:00:00Z",
  "expires_at": "2026-11-16T10:00:30Z",
  "answered_at": "2026-11-16T10:00:05Z",
  "score": 5
}
```

`answered_at` и `score` отсутствуют до ответа. Времена передаются в RFC 3339.
Состояния: `pending`, `displayed`, `answered`, `expired`.
UUID создаёт сервер; значения выше приведены для иллюстрации.

## Последовательность запросов

Сначала планшет обращается к `/state`, чтобы появиться в сети. Можно вместо
этого держать открытой страницу планшета. Примеры предполагают экспортированные
ключи `ADMIN_TOKEN` и `TABLET_TOKEN` (значение конкретного планшета).

```sh
export BASE_URL='http://127.0.0.1:8080'
curl -sS "$BASE_URL/api/tablets/reception-1/state" \
  -H "Authorization: Bearer $TABLET_TOKEN"

curl -sS -X POST "$BASE_URL/requests" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"reception-1"}'
```

Скопируйте `id` из ответа в `REQUEST_ID`. Приглашение действует 30 секунд
по умолчанию; состояние подключения — восемь секунд с последнего опроса.
Для ручной проверки удобнее держать вкладку планшета открытой.

```sh
export REQUEST_ID='UUID_ИЗ_ОТВЕТА'
curl -sS -X POST "$BASE_URL/api/tablets/reception-1/ack" \
  -H "Authorization: Bearer $TABLET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"id\":\"$REQUEST_ID\"}"

curl -sS -X POST "$BASE_URL/api/tablets/reception-1/answer" \
  -H "Authorization: Bearer $TABLET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"$REQUEST_ID\",\"score\":5}"
```

Повторная отправка той же оценки возвращает 200 с сохранённым ответом.
Другая оценка для отвеченного приглашения возвращает 409. Ответ на ещё
не отвеченное приглашение после срока — 410.

## Состояние экранов

Ответ планшету содержит `device_id`, `server_now`, `request`, `slideshow_url`
и `slideshow_configured`. `request` равен `null`, если действующего приглашения
нет; `slideshow_url` равен `/slideshow/` при подключённом источнике, иначе `""`.

Ответ сотруднику содержит `server_now`, `request_ttl_seconds`,
`slideshow_configured` и `devices`. Элемент `devices`: `id`, `name`, `online`,
`last_seen` (RFC 3339 или `null`), `request` (последнее приглашение или `null`).
Последнее приглашение включает закрытые состояния.

## Ошибки

Ошибки обработчиков и авторизации возвращаются в JSON:

```json
{"error":"expired","message":"Время для ответа истекло"}
```

| HTTP | `error` | Причина |
| --- | --- | --- |
| 400 | `invalid_json` | Тело не соответствует ожидаемому JSON |
| 400 | `unknown_device` | Неизвестный планшет при создании приглашения |
| 400 | `invalid_request`, `invalid_rating` | Некорректные данные или оценка вне 1–5 |
| 401 | `unauthorized` | Ключ отсутствует или неверен |
| 403 | `origin_denied` | Не разрешён источник запроса |
| 404 | `not_found` | Не найдено приглашение или оценка; приглашение принадлежит другому устройству |
| 404 | `unknown_device` | Неизвестный планшет в маршруте устройства |
| 409 | `device_offline` | Планшет не подключён |
| 409 | `active_request` | На устройстве уже есть активное приглашение |
| 409 | `already_answered` | Попытка изменить ответ или действие с закрытым приглашением |
| 410 | `expired` | Срок приглашения истёк |
| 500 | `storage_error` | Ошибка хранилища |
| 503 | `not_ready` | Проверка готовности не получила доступ к БД |

Ошибки маршрутизатора и статических файлов, включая 404/405, могут быть
текстовыми: общий JSON-формат на них не распространяется.

Совместимый `POST /rating` принимает `{"request_id":"…","score":5}`.
Он также требует существующего приглашения и соблюдает его жизненный цикл;
произвольный идентификатор не создаёт новую оценку.

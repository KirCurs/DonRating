# Запуск и эксплуатация

[English](operations.en.md)

## Запуск без Docker

Понадобятся Go 1.25.3, PostgreSQL и CLI `migrate` из golang-migrate. Выполняйте команды из корня репозитория. Пример предполагает, что в локальном PostgreSQL уже есть роль `ratingdon`.

```sh
createdb -h localhost -U ratingdon ratingdon
export DATABASE_URL='postgres://ratingdon@localhost:5432/ratingdon?sslmode=disable'
migrate -path migrations -database "$DATABASE_URL" up
go run ./cmd/feedback
```

Если PostgreSQL требует пароль, настройте аутентификацию для своего окружения. Базу и схему создают команды выше. Приложение само их не создаёт. Адрес по умолчанию — `127.0.0.1:8080`. Откройте `/admin` и `/tablet?device_id=reception-1`. Для доступа через loopback токены необязательны. Чтобы остановить сервер, нажмите Ctrl+C в его терминале.

## Конфигурация

При старте приложение читает переменные окружения. Пример приведён в [`.env.example`](../.env.example). Само Go-приложение файл `.env` автоматически не загружает. Docker Compose подставляет значения своим механизмом.

| Переменная | Назначение и значение по умолчанию |
| --- | --- |
| `APP_ADDR` | Адрес HTTP-сервера, по умолчанию `127.0.0.1:8080` |
| `DATABASE_URL` | Строка подключения pgx. Резервное значение — `host=/tmp port=5432 user=sh dbname=ratingdon`. Укажите свою строку явно |
| `DEVICES_JSON` | Массив устройств. По умолчанию `[{"id":"reception-1","name":"Ресепшен · планшет 1"}]` |
| `REQUEST_TTL` | Срок приглашения. По умолчанию `30s`, диапазон от `5s` до `10m` |
| `ADMIN_TOKEN` | Ключ сотрудника |
| `DEVICE_TOKENS_JSON` | Ключи устройств, например `{"reception-1":"token"}` |
| `SLIDESHOW_URL` | Полный HTTP(S)-адрес совместимого плеера. Пустое значение отключает прокси |
| `POSTGRES_PASSWORD` | Пароль для БД в Compose. Используется при инициализации PostgreSQL |
| `TEST_DATABASE_URL` | База для интеграционных тестов |

ID устройств должны быть уникальны. Допустимы 1–64 латинские буквы, цифры, `_` или `-`. Имя не может быть пустым. Если `APP_ADDR` доступен по сети, нужны ключ сотрудника и ключ каждого настроенного планшета длиной от 24 символов. Ключи должны различаться и не содержать пробельных или управляющих символов.

## Docker Compose

Команды первого запуска есть в [README](../README.md#getting-started). Конфигурация из репозитория запускает PostgreSQL 16, контейнер миграций и Go-приложение. Приложение стартует, когда БД готова и миграции выполнены. Данные лежат в именованном томе. Порт БД на хосте не публикуется.

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 migrate
```

Пересборка после изменения кода с прежними переменными окружения:

```sh
docker compose up --build -d --wait
```

Для существующего тома сохраните исходный пароль PostgreSQL. Перед изменениями схемы создайте резервную копию. Команда `docker compose down` сохраняет том, а `docker compose down -v` удаляет его данные.

## Миграции существующей БД

Остановите приложение, сделайте резервную копию и проверьте восстановление в отдельной базе. Храните копии вне Git. В примере используется адрес, который понимают и инструменты PostgreSQL, и `migrate`.

```sh
pg_dump --dbname="$DATABASE_URL" --format=custom --file=/tmp/ratingdon-before-migration.dump
migrate -path migrations -database "$DATABASE_URL" version
migrate -path migrations -database "$DATABASE_URL" up
migrate -path migrations -database "$DATABASE_URL" version
```

Повторный запуск примера перезапишет файл. Для регулярных копий используйте уникальные имена и защищённое хранилище. Текущая версия схемы — 4 с `dirty=false`.

| Версия | Изменение |
| --- | --- |
| 1 | Таблица `ratings` |
| 2 | Таблица `rating_requests` |
| 3 | Статусы и срок приглашений, ограничения и индексы |
| 4 | Постоянный реестр планшетов с хешами ключей |

Миграция 3 сохраняет существующие оценки. Старые приглашения без достоверного срока закрываются. Приглашения с оценкой считаются отвеченными, остальные — истёкшими. Сравните количество оценок до и после обновления.

Если `dirty=true`, проверьте, какие SQL-команды успели выполниться. `migrate force` меняет отметку версии. Исправление схемы выполняется отдельно. Перед откатом прочитайте соответствующие миграции, поскольку они могут удалить таблицы или столбцы.

## Подключение слайд-шоу

```sh
export SLIDESHOW_URL='http://slideshow-host:5000/slideshow/reception'
go run ./cmd/feedback
```

Подставьте адрес совместимого плеера. В Compose адрес должен быть доступен из контейнера. `localhost` внутри контейнера указывает на сам контейнер.

Адаптер обращается к маршрутам транслятора `/slideshow/<slug>`, `/api/time`, `/api/slideshow/slug/<slug>/status` и `/uploads/<filename>`. Точка входа прокси в приложении — `/slideshow/`. Контент по-прежнему настраивается во внешней системе.

## Сетевой доступ для планшетов

Стандартный Compose публикует HTTP только на `127.0.0.1`. Для ресепшена настройте HTTPS через обратный прокси по адресу, доступному планшетам. Передавайте заголовок `Host`, соответствующий адресу в браузере, поскольку API проверяет `Origin`. При запуске Go напрямую выберите сетевой `APP_ADDR` и задайте ключи. Передавайте Bearer-токены по защищённому каналу.

У сотрудника и каждого планшета свои ключи доступа. Ключи, заданные в окружении, меняются через обновление переменных, перезапуск приложения и замену ключей в интерфейсе.

## Тесты и диагностика

```sh
go test ./...
go vet ./...
go test -race ./...
```

Интеграционные тесты создают и удаляют уникальные схемы PostgreSQL. Используйте отдельную тестовую БД и роль с правом создавать схемы.

```sh
export TEST_DATABASE_URL='postgres://ratingdon@localhost:5432/ratingdon_test?sslmode=disable'
go test -race -count=1 ./...
```

Без `TEST_DATABASE_URL` тесты PostgreSQL пропускаются. Остальные тесты проверяют валидацию, HTTP-обработчики, конфигурацию и прокси слайдов.

| Симптом | Что проверить |
| --- | --- |
| Приложение сразу завершилось | Переменные окружения, связь с БД и доступность порта |
| `/ready` возвращает 503 | Подключение к PostgreSQL |
| Создание приглашения возвращает 409 `device_offline` | Открыта ли страница нужного планшета и опрашивает ли она `/state` |
| Создание приглашения возвращает 409 `active_request` | Действует ли предыдущее приглашение |
| 401 | Ключ сотрудника или устройства |
| 403 | `Origin` браузера и переданный `Host` |
| Плеер не загружается | `SLIDESHOW_URL`, сетевой доступ из приложения или контейнера и поддерживаемые маршруты |

Основной логгер пишет JSON в stderr. Обработчики `/health` и `/version` дополнительно выводят HTTP-метод в stdout. При SIGINT или SIGTERM сервер ждёт завершения HTTP-запросов до десяти секунд. Проверка подключения к БД при старте ограничена пятью секундами. После перезапуска статус подключения восстановится по запросам планшетов.

## Регистрация планшета

После миграции 4 добавьте планшет по имени в `/admin` и откройте полученную ссылку на устройстве. Регистрация вступает в силу сразу. Браузер сохраняет ключ в локальном хранилище. Устройства из конфигурации по-прежнему используют `DEVICE_TOKENS_JSON`. Зарегистрированные устройства предъявляют свой ключ даже через loopback. Храните ссылки в защищённом месте. Интерфейс пока не поддерживает отзыв ключей и переименование зарегистрированных устройств.

Для работы без оператора настройте киоск-режим ОС или браузера и отключите сон экрана в настройках планшета. Возможности полноэкранного режима и Wake Lock зависят от браузера и устройства.
